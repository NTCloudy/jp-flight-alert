# ✈️ JP Flight Alert：日本傳統航空便宜機票提醒

只看**傳統航空直飛**（華航、長榮、星宇、華信、日航、全日空、國泰），用你的**起降時段**和**天數**找台灣⇄日本的便宜來回機票。這個工具會在 **GitHub Actions 上每小時自動執行**，然後用 Email 通知你：

- 🔥 **超便宜，馬上寄信**：每人來回含稅 ≤ NT$8,000
- 👍 **划算，放進每日整理**：每人 ≤ NT$10,000
- 📉 **特別便宜，放進每日整理**：比這條航線過去 30 天的平均便宜 20% 以上
- 📣 **航空公司促銷消息，放進每日整理**：華航、長榮、星宇、日航、全日空、國泰的日本線促銷新聞
- 📰 **每日整理**每天早上 8:00 寄出，附上各目的地目前的最低價

> **這個工具只負責通知，不會幫你訂票。** 收到通知後，請點信裡的連結到 Google Flights 或航空公司官網自己訂。

## 🔎 目前的條件（`config.yaml`）

| 項目 | 設定 |
|---|---|
| 出發機場 | 桃園（TPE）、松山（TSA，只飛羽田） |
| 目的地 | 日本各地（沒有符合時段直飛的機場會自動略過，每週重查） |
| 航空公司 | 華航、長榮、星宇、華信、日航、全日空、國泰（廉航不在名單上） |
| 去程 | 台灣時間 10:00–14:00 起飛，日本時間 18:00 前抵達（最晚 18:30，超過 18:00 會標「稍晚抵達」） |
| 回程 | 日本時間 13:00–15:00 起飛，台灣時間 19:00 前抵達（最晚 20:00） |
| 天數 | 4～8 天，最想玩 5 天 |
| 人數 | 2 位大人、經濟艙（價格一律換算成**每人、來回、含稅**） |
| 查詢範圍 | 2 天後～180 天內出發 |

## ⚙️ 運作方式

1. **資料來源**：[Google Flights](https://www.google.com/travel/flights)（透過開源套件 [`fli`](https://github.com/punitarani/fli)），不需要任何 API 金鑰。
2. **分批查詢**：Google 不喜歡短時間大量查詢，所以把工作切成很多小項目（航線 × 天數 × 約 2 個月的出發日期），每小時只查「到期」的部分：
   - 5 天行程、近 2 個月出發：每 3 小時更新
   - 其他天數或比較遠的日期：每 6～24 小時更新
   - 被 Google 要求放慢（HTTP 429）時，會自動暫停 45 分鐘以上再繼續
3. **兩段式確認**：先用「日曆價」找出便宜的日期，再查實際航班，確認起降時間、航空公司、直飛都符合，才會通知你。
4. **不重複寄信**：同一個行程只寄一次，除非每人再便宜 NT$300 以上，或下架超過 12 小時後又出現。
5. **資料存放**：價格、通知紀錄存在這個 repo 的 `data` 分支，控制台直接讀取。

## 🔑 GitHub Secrets

在 **Settings → Secrets and variables → Actions** 設定（已設定好）：

| Name | 值 |
|---|---|
| `SMTP_USER` | 寄件 Gmail 地址 |
| `SMTP_PASSWORD` | Gmail 應用程式密碼（16 碼） |
| `NOTIFY_EMAIL` | 收通知的 Email |

## 🖥️ 在自己的電腦執行（選用）

```bash
pip install -r requirements.txt
python -m flight_alert plan                 # 看目前的條件和航線
python -m flight_alert scan --dry-run       # 查一次，只印出通知、不寄信
python -m flight_alert digest --dry-run     # 印出每日整理
python -m flight_alert test-email           # 寄測試信（需要上面三個環境變數）
python -m unittest discover -s tests -t . -v
```

## ⚠️ 限制

- Google Flights 沒有官方 API，`fli` 是讀它網頁背後的資料。Google 改版時可能暫時失效；**連續查詢失敗約 6 小時會寄信提醒你**。
- 價格是 Google Flights 查到的含稅總價，實際以航空公司結帳畫面為準；便宜的票常常很快賣完。
- GitHub 的排程偶爾會延遲或跳過，所以設定成每小時執行、每次查到期的資料。
- 公開 repo 60 天沒有任何更新時，GitHub 會停用排程；系統會自動做一次空白更新避免這件事。
